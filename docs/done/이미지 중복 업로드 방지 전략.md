# 이미지 중복 업로드 방지 전략

동일 이미지를 반복 업로드할 때 DB 레코드 중복 생성과 캐시 키 루트 변경을 방지한다.
클라이언트 측과 서버 측 두 단계로 중복을 차단한다.

---

## 1. 클라이언트 측 (ImgPrcPage.vue)

### 동작 방식
`setOriginalFile(file)` 호출 시, 이전 파일과 동일한지 비교하여 업로드를 스킵한다.

### 비교 기준
| 속성 | 설명 |
|------|------|
| `name` | 파일명 |
| `size` | 파일 크기 (bytes) |
| `lastModified` | 파일 수정 시각 (ms timestamp) |

### 로직
```
이전 파일과 (name, size, lastModified) 동일 AND originalFileId 존재
  → 업로드 API 호출 스킵
그 외
  → uploadFile(file) 호출 → fileId 갱신
```

### 효과
- 동일 파일 재선택 시 불필요한 네트워크 요청 제거
- `originalFileId`가 유지되므로 캐시 키 루트도 변경되지 않음

---

## 2. 서버 측 (SHA-256 content hash)

### 동작 방식
업로드 시 파일 바이트의 SHA-256 해시를 계산하고, DB에 동일 해시가 존재하면 기존 레코드를 반환한다.

### 흐름
```
POST /api/image-processing/upload
  1. data = file.read()
  2. content_hash = sha256(data).hexdigest()
  3. SELECT FROM t_file WHERE content_hash = ? LIMIT 1
     → 존재: 기존 레코드 반환 (파일 저장 안 함)
     → 미존재: 파일 저장 + INSERT (content_hash 포함) + 새 레코드 반환
```

## 4. 두 전략의 관계

클라이언트 dedup과 서버 dedup은 **상호 보완적**이다.

| 시나리오 | 클라이언트 | 서버 |
|----------|:----------:|:----:|
| 같은 브라우저에서 동일 파일 재선택 | **스킵** | - |
| 새 탭/세션에서 동일 파일 업로드 | 미감지 | **기존 반환** |
| 파일명은 다르지만 내용 동일 | 미감지 | **기존 반환** |
| 파일명·크기 동일하지만 내용 다름 | 스킵 가능성 | **새로 저장** |

클라이언트는 빠른 경로(네트워크 절약), 서버는 정확한 경로(해시 기반 보장)를 담당한다.
