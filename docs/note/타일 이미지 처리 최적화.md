# 타일 이미지 처리 최적화 포인트

## 현재 구조

```
_save_node_image()  → 썸네일(150px) 또는 원본 PNG를 디스크에 저장
_save_node_dzi()    → pyvips.dzsave()로 DZI 타일(256px, jpg Q=85)을 디스크에 저장
cleanup_cache()     → TTL(1h) + 용량(1GB) 기반 LRU 삭제
```

- 저장 경로: `uploads/cache/{file_id}/{node_id}.png`, `{node_id}_files/`
- 조건: `max(h,w) >= TILE_THRESHOLD(4000)` 이면 DZI, 아니면 원본 PNG
- 배치 처리 시 **모든 노드**에 대해 썸네일 PNG + (full_size면) DZI/원본 저장

---

## 최적화 포인트

### 1. 디스크 I/O 병목

**현상**: 노드마다 `cv2.imencode → write_bytes` + `dzsave` 실행. 노드 수가 많으면 동기 디스크 I/O가 전체 처리 시간을 지배.

**개선안**:
- **비동기 파일 쓰기**: `aiofiles` 또는 별도 스레드풀에서 디스크 쓰기 처리. 이미지 처리(CPU)와 I/O를 분리
- **메모리 버퍼 반환**: 썸네일을 디스크에 쓰지 않고 base64 또는 blob URL로 직접 반환. 디스크 저장은 DZI만
- **PNG → JPEG 전환**: 썸네일을 PNG(무손실) 대신 JPEG(Q=80)으로 저장하면 인코딩 속도 + 파일 크기 모두 개선

### 2. DZI 타일 재생성

**현상**: 파라미터만 바꿔도 `shutil.rmtree → dzsave` 전체 재생성. 고해상도 이미지(8K+)에서 수초 소요.

**개선안**:
- **해시 기반 캐시 히트**: `(node_id, prc_type, parameters)` 조합의 해시를 키로 사용. 동일 파라미터면 기존 타일 재활용
- **지연 생성(lazy)**: 배치 처리 시 DZI를 즉시 생성하지 않고, 프론트에서 zoom 요청 시에만 생성
- **증분 타일링**: 변경된 영역만 타일 갱신 (pyvips 기본 지원 없음, 커스텀 구현 필요)

### 3. 메모리 사용량

**현상**: `image.tobytes()` + `cv2.cvtColor(BGR→RGB)` 로 이미지 메모리를 복사. 고해상도에서 GB 단위 메모리 소비.

**개선안**:
- **pyvips 파이프라인 직접 사용**: OpenCV ndarray → pyvips 변환 없이, 원본 파일을 pyvips로 직접 로드하여 처리 체인 구성 (스트리밍 처리, 메모리 절약)
- **numpy 뷰 활용**: `tobytes()` 대신 `pyvips.Image.new_from_memory`에 ndarray 버퍼를 직접 전달 (이미 하고 있지만, BGR→RGB 복사를 줄일 수 있음)

### 4. 캐시 전략

**현상**: `cleanup_cache()`에서 `_dir_size()`가 모든 파일을 `rglob`으로 순회. 타일이 수천 개이면 느림.

**개선안**:
- **크기 메타데이터 파일**: 디렉토리 생성 시 `.size` 파일에 누적 크기 기록, cleanup 시 `rglob` 대신 메타 파일 참조
- **LRU DB 관리**: SQLite 또는 인메모리 dict로 `{file_id: size, mtime}` 관리
- **파일 개수 제한**: 타일 파일 수가 많으면 `rglob("*")` 자체가 느림. 디렉토리 단위 크기를 OS stat으로 추정

### 5. 썸네일 이중 저장

**현상**: `full_size=True`일 때 썸네일(150px)을 먼저 저장하고, 그 다음 DZI 또는 원본을 **다시** 저장. 저해상도 이미지는 `_save_node_image`가 2번 호출됨.

**개선안**:
- **단일 저장**: full_size면 원본/DZI만 저장하고, 썸네일 URL은 원본 URL + 리사이즈 쿼리파라미터로 대체
- **조건 분기 정리**: 저해상도 + full_size면 원본 한 번만 저장하고 썸네일은 생략 (프론트에서 `object-fit: contain`으로 축소 표시)

### 6. 동시 요청 처리

**현상**: 동일 `file_id`에 대해 동시에 배치 처리 요청이 오면 같은 디렉토리에 동시 쓰기 → 파일 충돌 가능.

**개선안**:
- **file_id 단위 락**: `asyncio.Lock` 또는 파일 락으로 동일 file_id 동시 처리 방지
- **임시 디렉토리 → 원자적 교체**: 결과를 임시 디렉토리에 쓴 뒤 `os.rename`으로 교체

### 7. 포맷 최적화

**현상**: DZI 타일이 JPEG Q=85, 썸네일이 PNG. 용도에 비해 비효율적인 조합.

**개선안**:
- **WebP 전환**: 타일을 WebP(Q=80)로 생성하면 JPEG 대비 25~35% 용량 절감. pyvips의 `suffix=".webp[Q=80]"` 지원
- **AVIF**: 더 높은 압축률이지만 pyvips 빌드에 따라 미지원. 브라우저 호환성 확인 필요

## 우선순위 제안

| 순위 | 항목 | 효과 | 난이도 |
|------|------|------|--------|
| 1 | 썸네일 PNG → JPEG 전환 | 인코딩 2~3배 빠름, 용량 절감 | 낮음 |
| 2 | DZI 지연 생성 (lazy) | 배치 처리 속도 대폭 개선 | 중간 |
| 3 | 해시 기반 DZI 캐시 히트 | 반복 처리 시 I/O 제거 | 중간 |
| 4 | 썸네일 이중 저장 제거 | 불필요한 I/O 제거 | 낮음 |
| 5 | 캐시 크기 메타 파일 | cleanup 속도 개선 | 낮음 |
| 6 | WebP 타일 포맷 | 디스크 + 네트워크 절감 | 낮음 |
| 7 | 비동기 파일 쓰기 | CPU/IO 병렬화 | 중간 |
| 8 | file_id 단위 락 | 동시 요청 안정성 | 중간 |
