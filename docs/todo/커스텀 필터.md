## 1. 아이디어

- 필터 함수 목록에 커스텀 필터함수 필요
- 커스텀 필터함수 작성은 파이썬 코드를 동적으로 적용시켜서 실험할 수 있어야 함
- 동적 필터함수를 관리할수 있는 방안이 필요함

## 2. 구현 방안 (exec + 화이트리스트 샌드박스)

### 2.1 핵심 개념

- 사용자가 Python 코드를 작성하면 `exec`로 동적 실행
- `__builtins__`를 차단하고 `cv2`, `np` 등 허용 모듈만 제공하는 샌드박스 환경
- 기존 필터와 동일하게 batch-tree 파이프라인에서 사용 가능

### 2.2 샌드박스 실행 엔진

```python
# app/services/custom_filter_service.py

ALLOWED_GLOBALS = {
    "__builtins__": {},       # 내장함수 차단 (import, open, exec 등 불가)
    "np": np,                 # numpy
    "cv2": cv2,               # OpenCV
    "math": math,             # 수학 함수
}

def execute_custom_filter(
    code: str,
    image: np.ndarray,
    params: dict[str, Any],
) -> np.ndarray:
    """커스텀 필터 코드를 샌드박스 환경에서 실행한다."""
    local_vars: dict[str, Any] = {
        "image": image.copy(),   # 원본 보호
        "params": params,
        "result": None,
    }
    exec(code, ALLOWED_GLOBALS, local_vars)

    result = local_vars.get("result")
    if not isinstance(result, np.ndarray):
        raise ValueError("코드 실행 결과 'result' 변수에 np.ndarray를 할당해야 합니다.")
    return result
```

### 2.3 사용자 코드 작성 규칙

사용자는 아래 변수를 사용하여 코드를 작성한다:

| 변수 | 타입 | 설명 |
|------|------|------|
| `image` | `np.ndarray` | 입력 이미지 (BGR) |
| `params` | `dict` | 사용자 정의 파라미터 |
| `result` | `np.ndarray` | **출력 이미지 (반드시 할당)** |

사용 가능한 모듈: `cv2`, `np`, `math`

```python
# 사용자 코드 예시 1: 커스텀 엣지 검출
gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
ksize = params.get("ksize", 3)
blur = cv2.GaussianBlur(gray, (ksize, ksize), 0)
edges = cv2.Canny(blur, 50, 150)
result = cv2.cvtColor(edges, cv2.COLOR_GRAY2BGR)
```

```python
# 사용자 코드 예시 2: 채널 분리 + 합성
b, g, r = cv2.split(image)
weight = params.get("weight", 1.5)
enhanced_r = np.clip(r * weight, 0, 255).astype(np.uint8)
result = cv2.merge([b, g, enhanced_r])
```

### 2.4 DB 스키마

```sql
CREATE TABLE t_custom_filter (
    id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    nm          VARCHAR(100)  NOT NULL,           -- 필터 이름
    description TEXT          DEFAULT '',          -- 설명
    code        TEXT          NOT NULL,            -- Python 코드
    params      JSONB         DEFAULT '{}'::JSONB, -- 기본 파라미터 정의 (key, type, default)
    version     INT           DEFAULT 1,           -- 버전 (수정 시 증가)
    created_at  TIMESTAMPTZ   DEFAULT now(),
    updated_at  TIMESTAMPTZ   DEFAULT now()
);
```

### 2.5 기존 시스템 통합

#### PrcType 확장

```python
# app/schemas/file.py
PrcType = Literal[
    # ... 기존 필터 ...
    "custom",  # 커스텀 필터 추가
]
```

#### 파라미터 모델

```python
# app/schemas/image_processing.py
class CustomFilterParams(BaseModel):
    model_config = ConfigDict(populate_by_name=True)
    filter_id: UUID = Field(..., alias="filterId", description="커스텀 필터 ID")
    parameters: dict[str, Any] = Field(default_factory=dict, description="사용자 정의 파라미터")
```

#### OPERATIONS / PARAM_MODELS 등록

`process_image` 함수는 수정하지 않는다.
기존 디스패치 구조(`OPERATIONS[prc_type]` → 함수 호출)를 그대로 활용하여,
`"custom"` 항목을 등록하면 `process_image`, `process_image_batch`, `process_image_batch_tree` 모두 자동 지원된다.

```python
# app/services/image_processing_service.py
PARAM_MODELS["custom"] = CustomFilterParams

def _op_custom(image: np.ndarray, params: CustomFilterParams) -> np.ndarray:
    filter_data = custom_filter_repo.find_by_id(params.filter_id)
    if not filter_data:
        raise ValueError(f"커스텀 필터를 찾을 수 없습니다: {params.filter_id}")
    return execute_custom_filter(filter_data["code"], image, params.parameters)

OPERATIONS["custom"] = _op_custom
```

```
process_image(prc_type="custom", ...)
  → OPERATIONS["custom"] = _op_custom
    → DB에서 코드 조회 (custom_filter_repo.find_by_id)
      → execute_custom_filter(code, image, params)  # 샌드박스 exec 실행
        → result (np.ndarray)
```

### 2.7 프론트엔드 연동

- 기존 batch-tree에서 `prcType: "custom"` 노드 추가 가능
- 파라미터에 `filterId`와 `parameters`를 전달하면 기존 파이프라인과 동일하게 동작
- 코드 에디터(Monaco Editor 등)를 통해 Python 코드 작성/수정 UI 제공

### 2.8 보안 고려사항

- `__builtins__: {}` → `import`, `open`, `exec`, `eval`, `__import__` 등 차단
- `image.copy()`로 원본 이미지 보호
- `result` 타입 검증 (`np.ndarray`만 허용)
- 실행 시간 제한 (timeout) 적용 검토 가능
- 내부 실험용 서버이므로 현재 수준의 샌드박스로 충분
